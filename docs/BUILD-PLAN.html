The five stages

A weekend· Ships: the same file, sound

Stabilize what you're already studying on

Nothing structural. This is the pass that stops the current file degrading while the rest gets built, so you never have a week without a working tool.

  • Drop the Google Fonts link and inline the three faces as base64, or fall back to the system stack — either way, no network on launch.
  • Disconnect the ResizeObserver when an ink host detaches, and reuse hosts across renders.
  • Round stroke coordinates to 3 decimals and simplify with Ramer–Douglas–Peucker on pointerup — roughly a tenfold cut in what ink costs you.
  • Stop practice answers from rewriting due dates. A chapter drill should record that it happened, not reschedule every card it touches.
  • Call navigator.storage.persist() so iOS stops treating your progress as disposable cache.
  • Reconcile the 638/639 count, and surface the export backup prompt on a cadence rather than only after a write has already failed.
Done whenThe file opens with Wi-Fi off, a two-hour annotated session doesn't approach the storage ceiling, and a chapter drill leaves your review queue untouched.
Week 1–2· Ships: installable on every device you own

Make it a real PWA

The single biggest quality gap is that the browser rebuilds 25 MB of base64 on every launch. Splitting content from code fixes the start time, the memory ceiling, and the storage ceiling in one move.

  • Vite + ES modules. Split the 2,400-line script along the seams you already wrote: icons, ecg, ink, search, srs, tutor, ui. No rewrite — the existing code moves mostly intact.
  • Extract the 408 figures to real files (/figures/COR_41_1.webp), referenced by URL. The service worker caches them, prefetching the next question's while you read the current one.
  • Questions to content/questions.json — 1.6 MB raw, roughly 380 KB gzipped, loaded async and seeded into IndexedDB on first run.
  • IndexedDB via Dexie for ink, notes, chats and review logs. localStorage keeps only preferences. Your existing export JSON becomes the migration path in.
  • Service worker (Workbox): precache the shell and question bank, runtime-cache figures. Real offline, including on a plane.
  • Manifest, maskable icons, iOS splash screens, display: standalone — so Add to Home Screen produces an app, not a bookmark.
  • Keep a build:standalone script that reassembles the single-file version. It's a genuinely good escape hatch and costs almost nothing to preserve.
Done whenFirst launch is under 1.5s, second under 400ms, airplane mode changes nothing, and a full annotation session survives an iPadOS update.
Week 3· Ships: scheduling worth trusting

Make the rating mean something

Right now the app asks you for an honest self-assessment and then schedules all four answers identically on first exposure. That's the central promise of the app, and it's the thing to get right.

  • Log every review, starting immediately. Card, rating, state, elapsed days, scheduled days, timestamp. This is the substrate you don't have — without it you can never re-fit or migrate a scheduler, and it's the one thing that can't be reconstructed retroactively.
  • Move to FSRS-5 (ts-fsrs): difficulty, stability and retrievability per card, tuned to your own history once you've logged a few thousand reviews.
  • Learning steps so the four buttons diverge on first sight — Again 1m, Hard 6m, Good 10m, Easy graduates at 4d.
  • Practice and review become separate signals. Chapter drills record an attempt; only the review queue reschedules. An explicit "count this as a review" toggle when you want both.
  • Mastery becomes predicted retrievability, not reps/3 — those chapter rings should mean "you'd get this right today", which is a claim you can actually check.
  • Interleave chapters by default. Blocked practice feels better and tests worse; the boards are interleaved.
  • Optional and high-value: a one-tap confidence rating before the options appear. Confident-and-wrong is the highest-priority error class there is, and nothing in the app currently detects it.
  • Rebuild stats around it: true retention curve, calibration plot, and a 30-day forecast of upcoming workload so exam week doesn't ambush you.
Done whenThe four buttons show four different intervals on a brand-new card, and your stats screen can tell you what you'd score today rather than what you scored once.
Week 4· Ships: a tutor that can see

Give Braunwald eyes and memory

The system prompt currently tells the tutor it cannot see the figure and should ask you what you observe. For 305 of 639 items the figure is the question. This is the largest single quality jump available anywhere in the app.

  • Send the figure. Pass the question's WebP with the prompt on figure items. An ECG, an echo still, a PV loop — the model can reason from the image instead of interrogating you about it.
  • Move the key behind a Cloudflare Worker. One key, held server-side, with a daily spend cap and a shared secret. No plaintext key in localStorage on four devices, and no re-pasting when you pick up the iPad.
  • A learning profile in the system prompt: rolling summary of weak chapters, the last twenty misses, and the notes you've written. The tutor should open a session already knowing where you're soft.
  • Thread memory across questions, so a concept taught in Valvular is available when the same principle resurfaces in Congenital.
  • Keep BM25 — it's genuinely good — and add an embedding index built once at import, scored hybrid. Concept recall where the words don't match.
  • Keep the "say you're unsure rather than invent a trial" instruction. It's the most important line in that prompt. Consider a citation-check pass over trial names before display.
Done whenYou can open a rhythm-strip question, ask "what's the mechanism here", and get an answer that starts from what's actually on the tracing.
Week 5–6· Ships: iPad, phone and laptop as one

One account, your devices, your data

Sync carries your data — reviews, notes, ink, chats. The question bank and figures stay local on each device, seeded from your own copy. Nothing about the ACC content goes to a server.

  • Supabase: magic-link auth, Postgres for cards and review logs, row-level security. Chosen over the Firebase skeleton in the repo because the review log is fundamentally relational and you'll want SQL over it.
  • Append-only review log = conflict-free sync. Two devices can't disagree about events that already happened. Cards and notes take last-write-wins per field on updated_at; ink syncs per stroke.
  • Offline-first throughout: the local IndexedDB stays the source of truth, sync is a background reconciliation. Losing signal mid-session must never cost you a card.
  • Later, if you want colleagues in: group streaks and per-chapter accuracy comparison, keyed by question ID. Structure without content — anyone joining brings their own bank.
Done whenYou answer on the iPad on the ward, open your laptop at home, and the queue is exactly where you left it.
Ongoing· Ships: confidence to keep changing it

Keep it honest

  • Playwright suite — boot, answer, rate a review, search, offline load, figure zoom. The smoke tests written during this review are the seed; they already caught the leak and the rating bug.
  • Content validator in CI: answer-key bounds, figure-count match, duplicate stems, option percentages. The same checks run in this review, on every import.
  • Lighthouse budget in CI: installable, performance above 90, no regressions on cold start.
  • Accessibility pass: visible focus states, labelled progress rings and charts, and the reduced-motion path you already partly honour extended to the ECG canvases.

What survives untouched

The BM25 index

The KEEP regex protecting -osis terms from over-stemming, and the boost that stops your own short notes being buried under 1,500-character commentaries.

The query weighting

Repeating your words four times against a clipped stem, so retrieval follows what you asked rather than the question you happen to be sitting on.

The teaching prompt

Mechanism first, work the distractors, and admit uncertainty rather than invent a trial citation. Right pedagogy, right safety posture.

The ECG engine

Gaussian PQRST synthesis with rhythm-specific models, deterministic irregularity for AF, reduced-motion aware. Original, offline, and genuinely nice.

Palm rejection

The four-second pen-priority window. Small detail, and the difference between usable and infuriating with a Pencil.

The network error copy

Captive portals, Files-app preview mode, VPN blocks. Written by someone who has debugged an iPad on a hospital network.

Risks worth naming now

  • iOS evicts storage for sites you don't install. Seven days of non-use can clear everything. persist() plus Add to Home Screen is the mitigation, and it's why Stage 1 matters more than it looks.
  • Keep the original export. Everything downstream is derived from it. Back it up somewhere that isn't a browser.
  • Cache Storage is not localStorage. Figures move to a quota measured in gigabytes rather than 5 MB — but iOS still reclaims it under pressure, so the service worker needs a re-fetch path, not an assumption.
  • FSRS needs history. Its parameters are fitted, so the review log has to start before the scheduler does. That's the one item in Stage 2 that can't wait for Stage 2.

The first move

Stage 0 is a weekend and touches nothing structural — you keep studying on the same file, minus the leak, the network dependency, the storage risk, and the schedule corruption. Stage 1 then buys back twelve seconds of every launch.

If you want to compress the arc: the review log from Stage 2 is worth adding during Stage 0, because it costs an afternoon now and is unreconstructable later.
